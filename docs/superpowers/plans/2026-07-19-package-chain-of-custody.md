# Package, Barcode & Chain-of-Custody Pipeline — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline, author = executor). Checkbox steps; every wave ends in a verified commit. Spec waves 1–22 map onto 11 implementation waves below.

**Goal:** A complete package lifecycle — intake, numbering/barcodes, labels, loading scans, exceptions, completeness, groups, delivery, POD snapshot, returns — on ONE scan pipeline, with an immutable chain of custody, mobile scanner UX, warehouse & dispatcher tooling, notifications, customer visibility, XLSX reports and enforced permissions.

**Architecture:** New `Modules/Packages` for the tracked-unit domain; the EXISTING `ScanService` remains the single scan pipeline and grows a package resolution branch (registry-first, CargoItem quantity-lines unchanged as the "not individually tracked" bucket). ScanEvent stays the raw ledger; `PackageEvent` is the immutable custody timeline. POD gains a second frozen snapshot column. New backend deps: PDFsharp (MIT) + QRCoder (MIT). No new FE deps (camera via native BarcodeDetector where available).

## Global Constraints

- Dutch UI; `area.action` permission codes; backend enforcement authoritative.
- All conventions from previous milestones hold: AuditableTenantEntity, manual TenantId predicates, soft-delete filters (`"IsDeleted" = false`), enum→string conversions, OperationResult records + controller Handle switches, audit after save, TenantNumbering for numbering, TimeProvider, migrations via `dotnet ef migrations add` (not auto-applied), naive-DateTime→UTC normalization on new endpoints.
- **One scan pipeline**: never fork ScanService; extend `SubmitAsync`'s resolution + the feedback DTOs. Never fake a successful scan; every invalid/duplicate scan is recorded and reported.
- **Chain of custody is append-only**: PackageEvent has no update/delete API; corrections append.
- Per wave: acceptance criteria = the listed tests + live HTTP check; run `dotnet build`+full tests, FE lint/tsc/test/build; review diff; commit `feat(packages): …`; never push.

## Locked design decisions

1. **Package ≠ CargoItem, one scanner.** `Package` (table `packages`) is the individually tracked unit; `CargoItem` stays the quantity-only line. A barcode submitted to the existing scan endpoints resolves FIRST against the tenant-wide package-barcode registry; hits run through the package processor (lifecycle + custody + outcome), misses fall through to the existing CargoItem ladder untouched. Mixed orders = both side by side; completeness reports "niet stukgevolgd" for cargo-only tallies.
2. **Package fields** (spec W1 verbatim): TenantId, TransportOrderId (FK Cascade), LoadingStopId/DeliveryStopId (FK SetNull; null = derived from order stops at scan time — stops are wholesale-replaced on order edit, so stop refs are best-effort pins), PackageNumber (immutable), BarcodeValue (current active), BarcodeType, ExternalBarcode, ExternalPackageReference, CustomerReference, Description, Quantity(12,2 default 1), UnitType enum {Package, Parcel, Colli, Pallet, Crate, RollContainer, Container, Document, Other} + UnitTypeLabel (free text when Other), WeightKg, VolumeM3, LengthCm/WidthCm/HeightCm, ParentPackageId (self-FK SetNull — the parent IS the pallet/group), IsMandatory (default true), IsFragile, RequiresTemperatureControl, RequiresSignature, CurrentLifecycleStatus, CurrentExceptionStatus {None, Open, Resolved}, audit base. Indexes: (TenantId, TransportOrderId), (TenantId, PackageNumber) unique filtered, (TenantId, CurrentLifecycleStatus).
3. **Barcode registry** `package_barcodes`: PackageId, Value, Type {Code128, QrCode, External}, IsActive, RetiredAt/RetiredByUserId/RetireReason. Unique (TenantId, Value) filtered !IsDeleted — duplicate protection across the tenant by constraint. Scanning a retired value → outcome `ReplacedBarcode` (warning, names the replacement). Relabel = retire + issue new active value + PackageEvent `Relabelled` (old/new in payload) + audit; original PackageNumber never changes. Internal value format: `{PackageNumber}-{8 crockford-base32 random}` (Code128-safe, non-guessable suffix; barcode knowledge grants zero access — every endpoint stays permission+tenant gated).
4. **Numbering**: TenantSettings + `PackageNumberPrefix` ("PKG-") / `PackageNumberNextValue` concurrency token; `TenantNumbering.SaveWithClaimedNumberAsync`; bulk creation claims a contiguous block inside one save callback.
5. **Lifecycle** enum: Created, Labelled, AwaitingLoading, Loaded, InTransit, AtStop, Delivered, PartiallyDelivered, DeliveryFailed, Refused, Missing, Damaged, Cancelled, ReturnPending, ReturnLoaded, ReturnedToDepot, ReturnedToSender, RedeliveryPlanned, Quarantined. Static `PackageLifecycleMachine` (map + `IsTerminal` {Delivered, ReturnedToDepot(final), ReturnedToSender, Cancelled} + resolution transitions Missing→Loaded/Cancelled/ReturnPending via controlled actions only). Illegal jumps (Delivered→Loaded, Cancelled→anything, Missing→Delivered) have no edges; server-side only.
6. **Chain of custody** `package_events` (append-only): PackageId, EventType enum (Created, NumberAssigned, Labelled, LabelReprinted, Relabelled, StatusChanged, LoadScan, LoadMissing, WrongPackageScan, UnknownBarcodeContext, UnloadScan, Delivered, Refused, PartialDelivery, DamageReported, MarkedMissing, ExceptionResolved, GroupAssigned, GroupRemoved, GroupBroken, MovedToTrip, Cancelled, DispositionSet, ReturnLoaded, ReturnedToDepot, ReturnedToSender, RedeliveryLoaded, Quarantined, DepartureOverride, PodFinalized), OldStatus?/NewStatus?, TripId?/StopId?/TransportOrderId?, UserId?/DriverId?, DeviceInfo?, BarcodeUsed?, ScanResult?, ScanEventId?, ExceptionId?, IsOverride, Notes?, Latitude/Longitude? (location architecture — nullable now, GPS later), ClientEventId?, OccurredAt. Index (TenantId, PackageId, OccurredAt).
7. **Scan integration**: `SubmitScanRequest` gains `ClientEventId Guid?`; `scan_events` gains `PackageId Guid?` + unique (TenantId, ClientEventId) filtered → idempotent retry returns the stored feedback (replay-safe by constraint). `ScanService.SubmitAsync`: registry lookup → package branch via internal `PackageScanProcessor` (validates tenant/user/order-on-trip/trip/stop/expected assignment/lifecycle/prior scans/group state; produces outcome from spec W6/W10 lists) → writes ScanEvent(+PackageId) + PackageEvent + lifecycle mutation on success outcomes; else legacy CargoItem ladder. `ScanFeedbackDto` gains `Package` block (number, description, destination stop, unit type, outcome, counters incl. loaded/expected + %). Load success: AwaitingLoading/Labelled/Created→Loaded; unload success at delivery stop: →Delivered (or AtStop→Delivered), with Refused/Damaged/Partial variants from request flags.
8. **Package exceptions REUSE ExecutionException**: add `PackageId Guid?` (SetNull) + type values {UnknownPackage, WrongRoutePackage, WrongStopPackage, IncompleteQuantity, UnreadableBarcode, LabelMissing, RejectedBeforeLoading} to the existing enum; photos/status/dispatcher notes/customer-visible flow already exist. New `package_exceptions.create/manage` permissions gate package-linked exception creation/resolution routes; resolution actions (found-and-loaded, removed, moved-to-trip, customer-informed, returned) are `PackageResolutionService` actions that transition lifecycle + append events + close the exception.
9. **Missing flow** (spec W7): from the loading checklist select expected package → confirm → ExecutionException(MissingPackage,PackageId) + lifecycle→Missing + PackageEvent(MarkedMissing) + notify dispatcher (`exception_reported` existing type) — never a fake scan; counters show missing separately.
10. **Completeness & departure** (spec W8): `TripLoadReadinessService.GetAsync(tripId)` → per-trip totals {expected, loaded, missing, damaged, wrongOrUnknown, cancelled, quantityOnlyLines, groups}. TenantSettings `DepartureRule` string {AllowWithWarning | RequireOverride | Block} (default RequireOverride). `TripService.ChangeStatusAsync(→InProgress)` consults readiness: incomplete + Block → refuse; RequireOverride → 409 + readiness payload unless caller passes override AND holds `warehouse.release_trip` (re-checked server-side) with mandatory reason → audit + PackageEvent(DepartureOverride, on each unresolved package) + notification. Blocking regardless of rule: wrong-route package loaded (severe) list in payload.
11. **Groups** (spec W9): parent Package (UnitType Pallet/RollContainer/Container) with children via ParentPackageId. Group endpoints: create-with-children, add/remove, break, group label. Scanning a parent barcode expands to children ONLY when composition non-empty, all children share the applicable trip/stop context and none is in a conflicting state — otherwise outcome `GroupNotScannable` listing per-child blockers; per-child results always itemized in feedback (`ChildResults`), never hidden.
12. **POD** (spec W11): `proofs_of_delivery` gains `PackageSummaryJson` (default "[]") — frozen `PodPackageLineDto(PackageNumber, Barcode, Description, UnitType, Outcome, ScannedAt?, ExceptionRefs[])` built at finalize; corrections copy it verbatim (same as scan summary). Finalize gate: packages expected at the stop must all be in a terminal-for-stop outcome (Delivered/Refused/DeliveryFailed/PartialDelivered/Missing-with-open-exception acknowledged) else refuse; `FinalizePodRequest.AcknowledgeOpenPackageExceptions bool` + note required when open exceptions exist (recorded in POD Notes + PackageEvent PodFinalized per package).
13. **Returns** (spec W12): DeliveryFailed/Refused packages require a disposition (`POST /api/packages/{id}/disposition` {ReturnToDepot, ReturnToSender, Redelivery, CustomerCollection, Quarantine} + note) → ReturnPending/RedeliveryPlanned/Quarantined; scan actions reuse existing ScanType.Return (→ReturnLoaded on vehicle), ScanType.Depot (→ReturnedToDepot), new ScanType.Redelivery (→RedeliveryLoaded); ReturnedToSender via disposition completion action. Custody events throughout; a failed delivery cannot rest without disposition (readiness/console surfaces "zonder bestemming").
14. **Labels** (spec W4): deps `PDFsharp` + `QRCoder`. `Code128Encoder` (subset B/C, hand-written, unit-tested against known vectors) renders bars as rects; QR via QRCoder matrix → rects. `package_labels` snapshot entity: PackageId, Version, SnapshotJson (all printed fields: tenant identity, package number, barcode value, order number, customer, loading/delivery location + stop sequence, customer ref, weight, unit type, handling instructions, fragile/ADR/temp flags), Format {Thermal100x150, A4}, PrintedAt/PrintedByUserId, Reason (reprints). PDF is regenerated deterministically FROM the snapshot — historical labels never change when order/customer data changes. Endpoints: single/bulk/reprint (`packages.relabel` for reprint+relabel), lifecycle Created→Labelled on first label. Bulk = one PDF, N pages (thermal) or 8-per-A4 grid.
15. **Mobile scanner** (spec W14): upgrade ScanPanel — camera scanning via native `BarcodeDetector` when available (feature-detected; fallback message), HID wedge + manual entry stay; debounce (same value within 1.5s ignored client-side), scan mode indicator (laden/lossen), big touch targets, recent list, counters + %; **offline queue implemented fully**: localStorage-persisted pending events with ClientEventId, auto-replay on reconnect (useOnlineStatus), per-item pending/failed/synced badges, server reconciliation via the idempotency constraint; vitest-covered queue module. Only then is offline scanning claimed.
16. **Warehouse module** (spec W15): permission `warehouse.view` + `warehouse.release_trip`; new role template `magazijn` (v1-of-itself: warehouse.view, scanning.view/execute, packages.view, package_exceptions.create, exceptions.view/create, warehouse.release_trip NOT default) created via template mechanism (reaches existing DBs); FE `/warehouse` — today's loading trips, per-trip loading list (packages+cargo, search, counters), scan mode, mark-missing, report wrong/damage, print labels, completeness widget, release button (permission-gated). No HR/profitability data anywhere on the surface (verified in 403 matrix).
17. **Dispatcher console** (spec W16): extend `/exceptions` into filterable console (open/closed, type, severity, date, trip, order, customer, driver, stop, package, assignee) + `AssignedToUserId` column on ExecutionException + actions (assign, investigate, resolve, move package to trip [revalidates target trip/stop; MovedToTrip event], cancel package, request redelivery, acknowledge, note, customer-visible toggle, override) — reusing the existing status machine + new resolution service. Notification deep links land here.
18. **Notifications** (spec W17): catalog types `package_missing`, `package_wrong_route`, `package_unknown_barcode`, `package_damaged`, `load_discrepancy`, `departure_override`, `package_delivery_failed`, `package_refused`, `package_return_required`, `pod_with_exceptions`, `scan_sync_failure` (client-reported), `package_relabelled`. Dedupe via the LinkPath `#fragment` window mechanism (key = package/stop scoped) so repeated scans collapse; immediate notifications via NotifyPermissionHoldersAsync.
19. **Customer/order visibility** (spec W18): order detail package summary (totals per status + progress) behind `packages.view`; customer-facing redacted DTO (`CustomerVisible` only: reference, high-level status {Onderweg/Geleverd/Probleem}, delivery result, POD link, permitted photos) — no internal notes/driver data/operational details; Klantportaal role gets `packages.view_customer`? No — reuse orders.view + server-side redaction path (`/api/transport-orders/{id}/packages/customer-view`) gated orders.view, always redacted. Internal view needs packages.view.
20. **Reports** (spec W19): extend KpiExportService pattern with `PackageReportService` — XLSX: package master list, load discrepancies, missing, damaged, delivery exceptions, returns, scan timeline, performance per customer/trip/driver; filters + criteria sheet + EU formats + text-only strings; `package_reports.export`.
21. **Permissions** (spec W20): new codes `packages.view/create/manage/cancel/relabel/export`, `scanning.override`, `package_exceptions.create/manage`, `warehouse.view`, `warehouse.release_trip`, `package_reports.export`. Spec's `scanning.load`/`scanning.unload` are DELIBERATELY mapped onto the existing `scanning.execute` (one scan permission; documented) — "add or reuse". Role deltas via **DefaultRoleUpgrades version 3**: planner += packages.view/create/manage/export, package_exceptions.manage, warehouse.view; dispatcher += packages.view, package_exceptions.create/manage, scanning.override, warehouse.view, warehouse.release_trip; management += all new view/manage/override/export codes; chauffeur += packages.view, package_exceptions.create; boekhouding += packages.view; new `magazijn` template per D16. Live 401/403 matrix in final wave.

### Wave P2 — Creation, bulk, Excel import (spec 3)

Endpoints under `/api/transport-orders/{id}/packages/...` + `/api/package-import/template`. FE: order detail "Colli" tab (list + create + bulk dialog + import dialog with preview table). Tests: bulk, import happy, duplicate detection, all-or-nothing rollback, partial commit report, injection, ambiguity refusal.

### Wave P3 — Labels (spec 4)
Deps PDFsharp+QRCoder; Code128Encoder + tests (known encodings incl. checksum); `LabelRenderService` (thermal + A4 grid) from `package_labels` snapshots; endpoints single/bulk/reprint + audit + Labelled transition; FE print buttons (order tab + package rows) with blob download. ### Wave P4 — Loading scans, package exceptions, missing flow, completeness, departure (spec 6+7+8)

### Wave P5 — Groups (spec 9)

Tests: parent scan all-good, one child conflicted → child failure visible + others processed? ### Wave P6 — Delivery scans, POD snapshot, returns (spec 10+11+12)
