# Internationalization & Localization Wave — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NL/FR/EN als volwaardige talen door het hele ERP: één canonical i18n-laag (bestaand `src/i18n` uitgebreid en app-breed gemount), persoonlijke + tenant-taal, kiosk-meertaligheid, machine-readable error codes, glossary/style-guide/developer-guide, en eliminatie van elke businesslogica op displaytekst.

**Architecture:** `stable domain value → translate() → NL/FR/EN display`; regionale weergave (datum/decimaal/tijdzone) blijft bij de bestaande tenant-settings (`utils/dates.ts`); `User.PreferredLanguageCode` wordt dé UI-taalbron voor interne én portaalgebruikers (write via nieuw `PUT /api/me/language`, read via `/api/auth/me`), resolutie user → tenant `DefaultLanguage` → `nl`; fouten krijgen een `code`-veld naast de bestaande `message`/`detail` (backward-compatible).

**Tech Stack:** bestaand dependency-vrij i18n (géén i18next — bewust minimal-dependency-beleid, gedocumenteerd), vitest-pariteits-/guardtests, .NET zonder IStringLocalizer (kleine eigen catalogi per bestaand `InvoicePdfStrings`-patroon).

**Spec:** de i18n-wave-opdracht in de sessieprompt (100 secties). Dit plan verwijst per taak naar §-secties.

## Global Constraints

- Harde regels (§6/§61/§82): geen businesslogica/permissies op vertaalde labels; geen nieuwe hardcoded user-facing strings; API-enumwaarden blijven stabiel (§63/§86 — geen opgeslagen waarden migreren).
- i18n ≠ regionale formattering (§3/§33): datums/nummers blijven via tenant-settings; alleen taalgebonden onderdelen (weekdag-/maandnamen, duur-notatie u/h, valuta-layout) worden locale-bewust.
- Keys semantisch/stabiel per namespace (`attendance.actions.clockIn`), nooit displaytekst als key (§5); NL = bron; FR/EN-keysets exact gelijk (bestaande pariteitstest, §53).
- FR = professioneel Belgisch transport-/HR-taalgebruik volgens `docs/localization/glossary.md` (§22/§23); aanspreekvorm per style-guide (§70/§71): NL informeel "je" (bestaande UI-conventie), FR "vous", EN neutraal imperatief.
- User-created data wordt nooit vertaald (§32); logging blijft technisch (§59); tenant-configureerbare lookups (Reference-module) blijven databankdata, geen statische JSON (§31/§85).
- Notificatie-beslissing (§28): optie A — gerenderde tekst blijft opgeslagen (historiek verandert nooit met vertaalbestanden mee); gedocumenteerd, params-kolom = toekomst.
- Migraties additief (§60/§96); alle bestaande suites groen per fase.

## Scopefasering (expliciet, §1 vs §98)

Volledig geconverteerd in deze wave: gedeelde UI-kit/layout/nav/commands/calendar, dashboard, intern portaal, Attendance+Kiosk+Driver Card (100%, §87), HR-cluster (employees, absences, leave-balance, issued-items, tank-cards, qualifications, HR-settings), Locations, Settings/Systeeminformatie/Backups, auth. Daarna subagent-batches met glossary voor de overige feature-dirs (orders, customers, tarification, planning, fleet, warehouse, …). De 4 kritieke label-op-de-wire-schendingen en beide fouttekst-branches worden overal gefixt, ongeacht module.

## Bewuste beslissingen

1. Eigen i18n-systeem uitbreiden i.p.v. i18next: bestaand, getest, dependency-vrijbeleid gedocumenteerd; pluralisatie one/other volstaat voor nl/fr/en.
2. `User.PreferredLanguageCode` = canonical UI-taal (intern + portaal, zelfde kolom/endpointsemantiek); `Employee.PreferredLanguageCode` blijft HR-/communicatie-/kioskbron; klanttaalvelden ongemoeid (§10/§11).
3. Notificaties: gerenderde tekst blijft (auditstabiliteit) — gedocumenteerd besluit A (§28).
4. Type-safety via missing-key-guardtest i.p.v. gegenereerde key-types (§55: niet overengineeren bij 3–5k keys).
5. Geen lazy loading v1: bundels zijn klein (~15KB/taal nu; geraamd <100KB/taal na volledige migratie) — gedocumenteerd meetpunt (§56/§83).
6. Machine-exports (pricing-round-trip) behouden Dutch headers als contract; handmatige exports per gebruikerstaal — begonnen met attendance (§66).
7. Tests blijven NL-asserties gebruiken (context-default = nl) — bewust: minimale churn, taalwissel apart getest.
